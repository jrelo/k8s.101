# ISSUES.md

Known limitations and planned improvements for k8s.101.
This is not a bug tracker, just a running list of things we know about.

---

## Parser

- Hand-rolled YAML parser does not handle multi-line block scalars (`|`, `>`), anchors/aliases (`&foo`, `*foo`), or inline nested mappings (`{key: val}`). Configs generated by Helm or Kustomize may parse incorrectly without warning.
- The passthrough serializer re-emits the entire merged document in its own style. Block scalars come out as quoted inline strings. Functionally equivalent but will produce noisy diffs in gitops workflows.

## Passthrough

- ~~Per-container unknown fields dropped on merge~~ -- fixed. Containers are now matched by name and merged field-by-field. `startupProbe`, container-level `securityContext`, `lifecycle` hooks all survive. A container removed from the form is dropped. A new container added in the form is appended. Pod-level unknowns were already safe.

## Missing resource kinds

- No StatefulSet (needs `volumeClaimTemplates`, `serviceName`, stable pod identity)
- No DaemonSet
- No multi-document export (Deployment + Service together in one file)

## Form gaps

- Ingress form supports one rule and one path only
- No `envFrom` field (configMapRef / secretRef) -- only explicit `env` key/value pairs
- Resource strings (`100m`, `128Mi`) are free-text with no format validation
- No `nodeSelector` field
- No `tolerations` field

## Validator

- `validate-yaml.py` only validates the five kinds k8s.101 exports. Everything else is skipped with a notice.
- No schema version awareness (e.g. `autoscaling/v1` vs `autoscaling/v2` differences not checked)
